# 安全与数据处理

[返回 README](../README.md) · [架构](architecture.md) · [安全策略](../SECURITY.md)

## 适用边界

这里描述的是当前源码中可见的本地控制，不是公共部署设计、数据加密保证、合规结论或第三方服务授权。应用被限制在可信本地操作员场景；网络暴露、共享主机、公共 Webhook、反向代理和多租户模式均不受支持。

## 访问控制

- `GPT_REGISTER_OPERATOR_TOKEN` 必须是启动进程环境中的非空值；缺失时 `SecuritySettings.from_environment()` 拒绝初始化。
- 登录使用常量时间比较。成功后客户端得到签名会话 cookie 和 CSRF 值，而不是操作员令牌本身。
- 会话 cookie 为 `HttpOnly`、`SameSite=Strict`，路径为 `/api`；代码将 `secure=False`，因为设计目标是本机回环 HTTP。**这不是 HTTPS 或公共站点配置。**
- 默认会话时长为 8 小时。可选 `GPT_REGISTER_SESSION_SECRET` 存在时用于会话签名；否则以操作员令牌派生签名材料。
- 受保护 API 接受已认证操作员的 Bearer 请求或有效签名会话；仅使用会话的 `POST`、`PUT`、`PATCH`、`DELETE` 还需 CSRF 校验。

## 网络边界

应用依次拒绝非回环 TCP 对端和不规范 Host，只接受 `127.0.0.1`、`localhost`、`[::1]`。它不信任转发请求头。API 响应由中间件设置 `Cache-Control: no-store`；应用没有配置 CORS 中间件。

邮件回调使用独立的 `GPT_REGISTER_EMAIL_WEBHOOK_TOKEN`，不复用操作员令牌。未配置或不匹配时，回调接口拒绝请求；读取并消费 OTP 仍须已认证操作员请求（Bearer 或会话）。不要将这个接口公开到 Internet，也不要把它当作通用入站服务。

外部 HTTP 客户端默认 `verify_ssl=True`，保持 TLS 证书与主机名验证。请求失败、代理故障或兼容性问题都不是禁用验证的理由。

## 数据分类与保存位置

| 数据 | 可见的本地位置/路径 | 风险与处理 |
| --- | --- | --- |
| 操作员令牌、会话签名材料、Webhook 令牌 | 仅启动进程环境 | 不写入示例、YAML、前端、命令行、浏览器存储或提交 |
| 提供方配置 | `config.yaml`、数据库设置记录 | 可能含密钥、密码、代理和服务端点；本机受控保存且不发布 |
| 账号、密码、邮箱、电话、OAuth/访问/刷新令牌 | 本地 PostgreSQL 主库；显式回退时的 `data/gpt_register.db` | 高敏感；不提交、上传、截图或以数据库副本交换。发布包只允许 schema-only 脱敏 SQL |
| 邮件内容与 OTP | 数据库的 OTP/事件相关记录 | 消费后会标记为已消费；源码未显示自动保留期或删除路径，因而不得假定它会自动清除，也不要公开复制 |
| 浏览器状态、会话和输出 | 浏览器资料、`output/`、运行目录 | 视作账号材料；发布前排除并独立扫描 |
| 任务事件、错误、日志 | 数据库和本地日志/输出 | 可能意外包含标识符、端点或敏感上下文；分享前逐项净化 |

默认配置中 `save_session` 与 `save_tokens` 为 `false`。这只表示默认配置开关，不消除数据库或其他运行路径可能持有的敏感数据，也不提供加密或自动删除。

## 最小化和响应

1. 只配置完成功能所需的最少外部凭据与数据。
2. 将运行目录、备份和浏览器资料限制给可信本地用户；不要同步到公共云盘或版本控制。
3. 输出任何诊断材料前，人工检查并移除令牌、密码、cookie、OTP、邮箱、账号标识、代理和真实 URL 参数。
4. 怀疑泄露时停止进程、撤销或轮换外部凭据、限制本地文件访问，并记录不含秘密的最少事实。
5. 漏洞细节必须遵循[SECURITY.md](../SECURITY.md)的发布前私密报告前提；尚未验证私密通道时不得公开披露。

## 发布边界

`.gitignore`、发布树检查与 CI 是防线，不是对当前本地工作目录的证明。Git 历史扫描只能在目标仓库存在后由工作流执行；发布者仍需在上传前对实际候选归档做最终人工和自动检查。详见[发布审计矩阵](release-audit.md)。
