## 公开源码发布的必要序列

1. 在干净的受控位置重新创建候选归档；不要复用含运行资料的工作目录打包结果。
2. 对候选归档执行秘密与敏感文件检查，人工检查配置、文档、截图和构建输入。
3. 在请求者指定且获授权的目标 GitHub 仓库中创建或验证仓库设置，启用私密漏洞报告并安装真实的私密公告链接；未完成时不公开发布。
4. 推送候选并确认 CI 与完整历史 Gitleaks 工作流在实际远程历史上通过。
5. 最后确认仓库可见性、Issue/PR 表单、分支保护和发布资产只包含预期源码。

## 后续的供应链与许可证工作

当前源码不宣称 Python 依赖已经锁定、可复现、具有完整 SBOM，或第三方许可证已经完整审计。应在任何相关完整性声明、二进制/容器发布或第三方材料再分发之前，完成与实际工件绑定的依赖锁定、SBOM、来源、许可证与 NOTICE 审查。

## 证据的正确表达

可以说“源码候选包含发布树与历史秘密扫描工作流”。不能说“历史已在本地扫描完毕”“当前工作目录没有运行资料”“私密漏洞报告已启用”“依赖完全可复现”或“第三方许可证已完整审计”，除非相应远程和发布工件证据已经产生并保留。
